# ime-crdt-matrix

日本語IME（変換中の未確定文字列）× 共同編集CRDTの衝突を、敵対的なタイミングで再現する治具と実測結果のマトリクス。

## なぜ

日本語入力には「変換中」という未確定状態がある。変換候補を眺めている間、その文字列はまだ文書に確定していない。一方で共同編集エンジンは文書の状態を常に同期しようとする。変換中に他人の編集が同じ段落に着弾したら何が起きるか——カーソルが飛ぶ、強制確定される、未確定文字列が二重化する、入力が消える。組み合わせによって壊れ方が違う。

英語圏の開発者はIMEを使わないので、この壊れ方は彼らのdogfoodingに映らない。散発的なissueはあるが、体系的な検証は存在しない。

凡例: ✅ 問題なし / ⚠️ 条件付きで壊れる / ❌ 壊れる / 未検証

### 検証するシナリオ

1. 変換中に、同じ段落の**前方**にリモート挿入が着弾する
2. 変換中に、同じ段落の**後方**にリモート挿入が着弾する
3. 変換中に、未確定文字列を**含む範囲**がリモートで削除される
4. 変換中に、リモートから段落分割・結合が着弾する

各組み合わせは `results/<同期層>-<エディタ層>.md` に記録し、次を必ず含む:

- 環境とバージョン、治具の場所
- シナリオごとの進捗表（観測 / 原因 / 残り）。段階の定義は各記録ファイル内に書く
- シナリオごとの症状と、原因が分かった場合はコードの参照（ファイル名と関数名）
- コードから導いただけで観測していない事項は「未観測」と明記する

## ステータス

- Yjs × ProseMirror: 手動治具で4シナリオ観測済み → [results/yjs-prosemirror.md](results/yjs-prosemirror.md)
- Yjs × CodeMirror: Chrome で4シナリオ観測済み → [results/yjs-codemirror.md](results/yjs-codemirror.md)
- 治具: `harness/<組み合わせ>/` で `pnpm run dev`。生ログは `results/*.jsonl`
